## **1. Differences between `var`, `let`, and `const`**

**Explanation:**

* `var` is function-scoped and hoisted; can be redeclared.
* `let` is block-scoped, not hoisted like `var`, cannot be redeclared in the same scope.
* `const` is block-scoped, cannot be reassigned, but objects/arrays can still be mutated.

**Example:**

```js
function testVar() {
  var a = 1;
  if(true) {
    var a = 2; // same variable, function-scoped
    console.log(a); // 2
  }
  console.log(a); // 2
}

function testLetConst() {
  let b = 1;
  const c = 5;
  if(true) {
    let b = 2; // new block-scoped variable
    // c = 10; // Error: Assignment to constant
    console.log(b); // 2
  }
  console.log(b); // 1
}
```

---

## **2. Explain hoisting in JavaScript**

**Explanation:**

* Variables and function declarations are “hoisted” to the top of their scope.
* `var` is hoisted and initialized as `undefined`.
* `let` and `const` are hoisted but in Temporal Dead Zone (TDZ), so accessing before declaration throws an error.

**Example:**

```js
console.log(a); // undefined
var a = 5;

console.log(b); // ReferenceError
let b = 10;

hoistedFunc(); // Works
function hoistedFunc() { console.log('Hoisted!'); }
```

---

## **3. Function declarations vs function expressions**

**Explanation:**

* Function declarations are hoisted, can be called before definition.
* Function expressions (including arrow functions) are not hoisted.

**Example:**

```js
// Function Declaration
sayHi(); // Works
function sayHi() { console.log('Hi'); }

// Function Expression
const greet = function() { console.log('Hello'); };
// greet(); // Works only after this line
```

---

## **4. Arrow functions and `this`**

**Explanation:**

* Arrow functions don’t have their own `this`; they inherit `this` from the enclosing scope.
* Regular functions have their own `this` depending on how they are called.

**Example:**

```js
const obj = {
  value: 10,
  regular: function() { console.log(this.value); }, // 10
  arrow: () => console.log(this.value) // undefined in this context
};
obj.regular();
obj.arrow();
```

---

## **5. Closures and use case**

**Explanation:**

* A closure is a function that retains access to its lexical scope even after outer function has executed.
* Commonly used for data encapsulation, private variables, memoization.

**Example:**

```js
function counter() {
  let count = 0;
  return function() {
    count++;
    return count;
  };
}
const increment = counter();
console.log(increment()); // 1
console.log(increment()); // 2
```

---

## **6. Difference between `==` and `===`**

**Explanation:**

* `==` checks value after type coercion.
* `===` checks value **and** type (strict equality).

**Example:**

```js
console.log(5 == '5'); // true
console.log(5 === '5'); // false
```

---

## **7. Event loop and call stack**

**Explanation:**

* JS is single-threaded; call stack executes functions synchronously.
* Event loop handles asynchronous tasks by moving callbacks from task queues (macro/microtasks) to the stack.

**Example:**

```js
console.log('Start');
setTimeout(() => console.log('Timeout'), 0);
Promise.resolve().then(() => console.log('Promise'));
console.log('End');

// Output:
// Start
// End
// Promise
// Timeout
```

---

## **8. Synchronous vs asynchronous code**

**Explanation:**

* Synchronous: Executes line by line, blocking next operation.
* Asynchronous: Executes in background, non-blocking, uses callbacks, promises, async/await.

**Example:**

```js
// Synchronous
console.log('1');
console.log('2');

// Asynchronous
setTimeout(() => console.log('3'), 0);
console.log('4');
```

**Output:** `1 2 4 3`

---

## **9. Promises**

**Explanation:**

* A Promise represents a value that may be available now, in the future, or never.
* States: `pending`, `fulfilled`, `rejected`.

**Example:**

```js
const promise = new Promise((resolve, reject) => {
  setTimeout(() => resolve('Done'), 1000);
});

promise.then(result => console.log(result)).catch(err => console.error(err));
```

---

## **10. Async/await**

**Explanation:**

* Syntax sugar over Promises; makes asynchronous code look synchronous.
* Must use `try/catch` to handle errors.

**Example:**

```js
async function fetchData() {
  try {
    const response = await fetch('https://jsonplaceholder.typicode.com/todos/1');
    const data = await response.json();
    console.log(data);
  } catch (err) {
    console.error(err);
  }
}
fetchData();
```

## **11. Difference between `null` and `undefined`**

**Explanation:**

* `undefined`: Variable declared but not assigned a value.
* `null`: Explicitly assigned “no value”.

**Example:**

```js
let a;
console.log(a); // undefined

let b = null;
console.log(b); // null

console.log(typeof a); // undefined
console.log(typeof b); // object (historical JS quirk)
```

## **12. Difference between `call`, `apply`, and `bind`**

**Explanation:**

* `call`: Invokes function, arguments passed individually.
* `apply`: Invokes function, arguments passed as array.
* `bind`: Returns a new function with bound `this` and optional arguments.

**Example:**

```js
function greet(greeting, name) {
  console.log(`${greeting} ${name}`);
}
greet.call(null, 'Hello', 'Alice'); // Hello Alice
greet.apply(null, ['Hi', 'Bob']); // Hi Bob
const greetBob = greet.bind(null, 'Hey', 'Bob');
greetBob(); // Hey Bob
```

---

## **13. Prototypal inheritance**

**Explanation:**

* JavaScript objects inherit properties and methods from another object (prototype).
* Modern JS uses classes, but under the hood it’s prototypal.

**Example:**

```js
const parent = {
  greet() { console.log('Hello'); }
};
const child = Object.create(parent);
child.greet(); // Hello
```

---

## **14. Classical vs prototypal inheritance**

**Explanation:**

* Classical inheritance (like Java, C#) uses classes and instances.
* Prototypal inheritance uses objects inheriting from other objects directly.

**Example (Class):**

```js
class Person {
  constructor(name) { this.name = name; }
  greet() { console.log(`Hello ${this.name}`); }
}
const p = new Person('Alice');
p.greet(); // Hello Alice
```

**Example (Prototype):**

```js
const person = {
  greet() { console.log('Hi'); }
};
const student = Object.create(person);
student.greet(); // Hi
```

## **15. JavaScript modules: ES6 vs CommonJS**

**Explanation:**

* **ES6 Modules:** `import/export`, statically analyzed, run in strict mode, browser and Node supported.
* **CommonJS:** `require/module.exports`, Node.js only, dynamic loading.

**Example (ES6):**

```js
// math.js
export const add = (a,b) => a+b;

// main.js
import { add } from './math.js';
console.log(add(2,3)); // 5
```

**Example (CommonJS):**

```js
// math.js
module.exports.add = (a,b) => a+b;

// main.js
const { add } = require('./math.js');
console.log(add(2,3)); // 5
```

## **16. Shallow copy vs deep copy**

**Explanation:**

* **Shallow copy:** Copies top-level properties; nested objects still reference the original.
* **Deep copy:** Recursively copies all levels; no shared references.

**Example:**

```js
const obj = { a:1, b:{ c:2 } };
// Shallow copy
const shallow = {...obj};
shallow.b.c = 99;
console.log(obj.b.c); // 99

// Deep copy
const deep = JSON.parse(JSON.stringify(obj));
deep.b.c = 0;
console.log(obj.b.c); // 99 (unchanged)
```

---

## **17. Cloning objects and arrays**

**Explanation:**

* Objects: `Object.assign({}, obj)` or `{...obj}` (shallow), `JSON.parse(JSON.stringify(obj))` (deep).
* Arrays: `[...arr]` or `arr.slice()`.

**Example:**

```js
const arr = [1,2,3];
const cloneArr = [...arr];
cloneArr.push(4);
console.log(arr); // [1,2,3]
console.log(cloneArr); // [1,2,3,4]
```

## **18. `Object.freeze()` vs `Object.seal()`**

**Explanation:**

* `freeze()`: Prevents adding, removing, or modifying properties.
* `seal()`: Prevents adding/removing properties but allows modification of existing ones.

**Example:**

```js
const obj1 = { a:1 };
Object.freeze(obj1);
obj1.a = 2; // ignored
console.log(obj1.a); // 1

const obj2 = { b:1 };
Object.seal(obj2);
obj2.b = 2; // allowed
obj2.c = 3; // ignored
console.log(obj2); // { b:2 }
```

## **19. How `this` works in different contexts**

**Explanation:**

* Global context: `this` → `window` (browser) or `global` (Node).
* Object method: `this` → object.
* Class constructor: `this` → instance.
* Arrow function: `this` → lexical scope.

**Example:**

```js
console.log(this); // window (browser)

const obj = { val:10, method() { console.log(this.val); } };
obj.method(); // 10

class MyClass { constructor(val){ this.val = val; } }
const inst = new MyClass(5);
console.log(inst.val); // 5

const arrow = () => console.log(this);
arrow(); // window (lexical)
```

## **20. Difference between `window`, `global`, and `this`**

**Explanation:**

* `window`: Browser global object.
* `global`: Node.js global object.
* `this`: Context-dependent, can refer to `window/global` or an object depending on scope.

**Example:**

```js
console.log(window); // Browser global
console.log(global); // Node global
console.log(this); // window in browser, {} in Node module
```

## **21. What are IIFEs (Immediately Invoked Function Expressions) and why are they used?**

**Explanation:**

* An IIFE is a function that runs immediately after it’s defined.
* Used to create a **private scope**, avoiding polluting the global namespace.
* Common in older JS before modules existed.

**Example:**

```js
(function() {
  const privateVar = 'I am private';
  console.log(privateVar); // I am private
})();

// console.log(privateVar); // Error: not defined
```

## **22. Difference between `map`, `forEach`, `filter`, `reduce`**

**Explanation:**

* `forEach`: Iterates array, returns undefined.
* `map`: Iterates array, returns new array of same length.
* `filter`: Iterates, returns new array with elements passing condition.
* `reduce`: Reduces array to single value.

**Example:**

```js
const arr = [1,2,3,4];

// forEach
arr.forEach(x => console.log(x)); // 1 2 3 4

// map
const squared = arr.map(x => x*x);
console.log(squared); // [1,4,9,16]

// filter
const even = arr.filter(x => x%2===0);
console.log(even); // [2,4]

// reduce
const sum = arr.reduce((acc, curr) => acc+curr, 0);
console.log(sum); // 10
```

## **23. Difference between `setTimeout` and `setInterval`**

**Explanation:**

* `setTimeout`: Executes a function **once** after delay.
* `setInterval`: Executes a function **repeatedly** at intervals.
* Both return IDs which can be cleared with `clearTimeout` or `clearInterval`.

**Example:**

```js
setTimeout(() => console.log('Once after 1s'), 1000);

const intervalId = setInterval(() => console.log('Every 2s'), 2000);
setTimeout(() => clearInterval(intervalId), 7000); // stops after 7s
```

## **29. WeakMap and WeakSet**

**Explanation:**

## **30. JS decorators (proposal stage)**

**Explanation:**

* Decorators are functions that modify classes or methods.
* Still a stage 3 proposal (not fully standard).
* Used for logging, validation, etc.


## **31. What is event delegation and why is it useful?**

**Explanation:**

* Event delegation is a technique where a **parent element handles events** for its child elements using **event bubbling**.
* Reduces memory usage by attaching fewer event listeners.
* Useful for dynamic elements added later.

**Example:**

```js
const list = document.getElementById('list');

list.addEventListener('click', (e) => {
  if (e.target.tagName === 'LI') {
    console.log('Clicked item:', e.target.textContent);
  }
});

// Works even if new <li> elements are added dynamically
```

## **32. Explain debouncing and throttling**

**Explanation:**

* **Debounce:** Ensures a function runs **after a delay** since the last call (useful for search input).
* **Throttle:** Ensures a function runs **at most once** per interval (useful for scroll events).

**Example (Debounce):**

```js
function debounce(fn, delay) {
  let timer;
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

window.addEventListener('resize', debounce(() => console.log('Resized!'), 300));
```

**Example (Throttle):**

```js
function throttle(fn, limit) {
  let inThrottle;
  return function(...args) {
    if (!inThrottle) {
      fn.apply(this, args);
      inThrottle = true;
      setTimeout(() => inThrottle = false, limit);
    }
  };
}

window.addEventListener('scroll', throttle(() => console.log('Scrolling'), 500));
```

## **33. Shallow equality vs deep equality**

**Explanation:**

* **Shallow equality:** Only compares **top-level properties**.
* **Deep equality:** Compares **all nested properties recursively**.

**Example:**

```js

const obj2 = { a: 1, b: { c: 2 } };

// Shallow equality
console.log(obj1.b === obj2.b); // false

// Deep equality
function deepEqual(a, b) {
  return JSON.stringify(a) === JSON.stringify(b);
}
console.log(deepEqual(obj1, obj2)); // true
```

## **38. How does JSON.stringify handle circular references?**

**Explanation:**

* `JSON.stringify` **cannot handle circular references**; it throws `TypeError`.
* Workarounds: remove circular references or use custom replacer.

**Example:**

```js
const obj = {};
obj.self = obj;

// Using replacer
const json = JSON.stringify(obj, (key, value) => key === 'self' ? undefined : value);
console.log(json); // {}
```

**Explanation:**

## **48. Explain memoization and provide an example**

**Explanation:**

* Memoization stores results of expensive function calls to avoid recalculation.

**Example:**

```js
function memoize(fn) {
  const cache = {};
  return function(...args) {
    const key = args.toString();
    if (cache[key]) return cache[key];
    const result = fn(...args);
    cache[key] = result;
    return result;
  };
}

const fib = memoize(function(n) {
  if (n <= 1) return n;
  return fib(n-1) + fib(n-2);
});

console.log(fib(10)); // 55
```

## **49. Difference between mutable and immutable objects in JS**

* **Mutable objects:** Can be modified after creation (e.g., arrays, objects).
* **Immutable objects:** Cannot be changed after creation (e.g., strings, numbers).

**Example:**

```js
let arr = [1,2];
arr.push(3); // mutable
console.log(arr); // [1,2,3]

let str = 'Hello';
str[0] = 'h'; // ignored
console.log(str); // Hello (immutable)
```

## **50. Difference between `Object.create()` and class-based objects**

**Explanation:**

* `Object.create(proto)`: Creates a new object with the given prototype, simpler prototypal inheritance.
* Classes: syntactic sugar over prototypal inheritance, more structured for OOP.

**Example (Object.create):**

```js
const parent = { greet() { console.log('Hello'); } };
const child = Object.create(parent);
child.greet(); // Hello
```

**Example (Class):**

```js
class Parent {
  greet() { console.log('Hello'); }
}
const child2 = new Parent();
child2.greet(); // Hello
```

## **51. What are Proxy and Reflect in JavaScript?**

**Explanation:**

* **Proxy:** Allows you to define custom behavior for fundamental operations on objects (get, set, delete, etc.).
* **Reflect:** Provides default methods corresponding to object operations; often used with Proxy.

**Example:**

```js
const target = { name: 'Alice' };

const handler = {
  get: (obj, prop) => {
    console.log(`Getting ${prop}`);
    return obj[prop];
  },
  set: (obj, prop, value) => {
    console.log(`Setting ${prop} to ${value}`);
    obj[prop] = value;
    return true;
  }
};

const proxy = new Proxy(target, handler);
console.log(proxy.name); // Logs: Getting name → Alice
proxy.age = 25; // Logs: Setting age to 25
```

**Example with Reflect:**

```js
const handler2 = {
  set: (obj, prop, value) => {
    console.log(`Setting ${prop} to ${value}`);
    return Reflect.set(obj, prop, value); // default behavior
  }
};
```

## **52. How does WeakRef work in modern JavaScript?**

**Explanation:**

* **WeakRef** allows referencing an object **without preventing garbage collection**.
* Useful for caching without memory leaks.
* Objects referenced only by WeakRef can be collected.

**Example:**

```js
let obj = { data: 'important' };
const weakRef = new WeakRef(obj);

console.log(weakRef.deref()); // { data: 'important' }

obj = null; // object can be garbage collected
// weakRef.deref() may now return undefined
```

## **53. Difference between event bubbling and event capturing**

**Explanation:**

* **Event bubbling:** Event propagates **from target element up to ancestors**. Default behavior.
* **Event capturing:** Event propagates **from root down to target element**. Use `{ capture: true }`.

**Example:**

```js
document.getElementById('parent').addEventListener('click', () => console.log('Parent'), false); // bubbling
document.getElementById('parent').addEventListener('click', () => console.log('Parent Capturing'), true); // capturing

document.getElementById('child').addEventListener('click', () => console.log('Child'));
```

Clicking child → Output:
`Parent Capturing` → `Child` → `Parent`

## **54. Explain JavaScript’s `new.target` meta-property**

**Explanation:**

* `new.target` is used inside a constructor to **check if the function/class was called with `new`**.
* Helps enforce class instantiation rules.

**Example:**

```js
function Person(name) {
  if (!new.target) {
    throw 'Must use new';
  }
  this.name = name;
}

const p = new Person('Alice'); // Works
// Person('Bob'); // Throws: Must use new

class Animal {
  constructor(type) {
    console.log(new.target.name); // Logs class name
  }
}
new Animal('Dog'); // Animal
```

## **55. How do you handle concurrency in JavaScript?**

**Explanation:**

* JS is single-threaded but handles concurrency via **event loop, async functions, Promises, Web Workers**.
* Async operations (network, timers) run in **background**, allowing non-blocking execution.
* For CPU-intensive tasks, use **Web Workers** to offload computation.

**Example (Promise concurrency):**

```js
const urls = ['url1', 'url2', 'url3'];
Promise.all(urls.map(url => fetch(url).then(res => res.json())))
  .then(results => console.log(results))
  .catch(err => console.error(err));
```

**Example (Web Worker):**

```js
// worker.js
onmessage = function(e) { postMessage(e.data * 2); }

// main.js
const worker = new Worker('worker.js');
worker.onmessage = e => console.log('Result:', e.data);
worker.postMessage(10); // Result: 20
```
